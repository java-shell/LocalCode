# TurboVec / GraphRAG – External Namespace Export

## 1. Overview

TurboVec is a lightweight vector‑storage engine that powers the GraphRAG retrieval layer used by LocalCode.  
The implementation lives in two complementary parts:

| Layer | File(s) | Responsibility |
|-------|---------|----------------|
| **Node (frontend/backend)** | `llm-ide/src/backend/turboVecMemory.ts` | Handles high‑level API (`store`, `retrieve`) and serialises data to disk. |
| **Python bridge** | `llm-ide/src/backend/turbovec_bridge.py` | Executes the actual vector operations (FAISS/Annoy) via a CLI interface. |

The two layers communicate through JSON over stdin/stdout, allowing the Node runtime to remain lightweight while delegating heavy‑lifting to Python.

## 2. Namespace Concept

A *namespace* is simply a logical bucket that isolates data and its metadata.  
All files for a namespace are stored under:

```
<project_root>/llm-ide/src/backend/turbovec_memory/<namespace>/
```

Typical contents:

| File | Purpose |
|------|---------|
| `memory.tvec` | Vector index (FAISS/Annoy) serialized to disk. |
| `memory.jsonl` | One‑line JSON per item containing id, text, source, metadata, timestamps. |

### Creating a Namespace

1. **Via Node API**  
   ```ts
   import { TurboVecMemory } from './turboVecMemory';

   const memory = new TurboVecMemory(
     '/path/to/turbovec_memory',
     '/path/to/turbovec_bridge.py'
   );
   await memory.store(config, [
     { text: 'Hello world', source: 'example.txt' },
     // …
   ], { namespace: 'my_namespace' });
   ```

2. **Via Python CLI**  
   ```bash
   python turbovec_bridge.py store \
     --namespace my_namespace \
     --items-file data.jsonl
   ```
   `data.jsonl` is a newline‑delimited JSON file with the same shape as the Node payload.

## 3. Ingesting Data

### Payload Shape (Node)

```ts
await memory.store(config, items, options);
```

- `config`: `LLMConfig` with the embedding endpoint details.
- `items`: Array of `{ text: string, source: string, metadata?: Record<string, unknown> }`.
- `options`: `{ namespace: string, replaceSources?: string[] }`.

The `store` method:

1. Loads the current index for the namespace (creates one if missing).  
2. Adds each item's vector embedding (generated by the LLM client).  
3. Persists the updated index (`memory.tvec`) and metadata file (`memory.jsonl`).

### Payload Shape (Python)

```json
{
  "action": "store",
  "namespace": "my_namespace",
  "items": [
    {"text":"…","source":"…","metadata":{}}
  ],
  "replaceSources": ["old.txt"]
}
```

The bridge parses the JSON, calls `faiss.IndexFlatL2` (or other backend) to add vectors, and writes metadata.

## 4. Retrieval API

```ts
memory.retrieve(config, 'search query', {
  namespace: 'my_namespace',
  k: 5,
  vectorK: 10,
  maxHops: 3
});
```

- `k`: number of final results returned.  
- `vectorK`: initial seed size before graph expansion.  
- `maxHops`: limits how far the graph traversal can go.

The method returns an array of `RetrievedMemoryItem` objects, each containing:

| Field | Description |
|-------|-------------|
| `id` | Unique integer ID in the namespace. |
| `text` | Original text snippet. |
| `source` | Source file or identifier. |
| `score` | Similarity score (higher is better). |
| `metadata` | Optional user‑supplied metadata. |

## 5. Exporting a Namespace for LocalCode

1. **Package the namespace directory**  
   ```bash
   tar czf my_namespace.tar.gz llm-ide/src/backend/turbovec_memory/my_namespace/
   ```

2. **Distribute the archive** (e.g., via Git, S3, or local copy).

3. **Import in LocalCode** – pass the extracted path as the first constructor argument:

```ts
const memory = new TurboVecMemory(
  '/path/to/turbovec_memory',
  '/path/to/turbovec_bridge.py'
);
```

The same namespace string (`my_namespace`) is used for all subsequent `store`/`retrieve` calls.

## 6. Spin‑Off Side App Pattern

A minimal side app can be a Node script that:

1. Reads a CSV/JSON file of domain data.  
2. Calls the Python bridge to ingest it into a dedicated namespace.  
3. Optionally exposes an HTTP API for retrieval, delegating to `TurboVecMemory`.

Example skeleton (`ingest.js`):

```js
const { spawnSync } = require('child_process');
const fs = require('fs');

const data = JSON.parse(fs.readFileSync('data.json', 'utf8'));

spawnSync('python3', [
  'llm-ide/src/backend/turbovec_bridge.py',
  'store',
  '--namespace', 'domain_ns',
  '--items-file', 'data.jsonl'
], { stdio: 'inherit' });
```

This script can be wrapped in a Docker container or run as a cron job, producing a ready‑to‑use namespace for any LocalCode instance.

## 7. Key Takeaways

- **Namespaces** are simple directory structures; no database required.  
- **Ingestion** is performed via the `store` API (Node) or the Python CLI.  
- **Retrieval** uses graph expansion and vector similarity, configurable per call.  
- **Export/Import** is just copying the namespace folder; LocalCode can consume it out of the box.
